# 개장 1시간 거래소 간 동일 자산 평균회귀

원문: [Bybit–Hyperliquid 가격차이 분석 정리](https://app.notion.com/p/Bybit-Hyperliquid-2026-11-03-1-40faec444ec880ecb856ee66a4a69596).

## 원문에서 확인한 사실

- 2026-11-03 14:30–15:30 UTC, Bybit–Hyperliquid의 1초 자료다.
- BTC 가격차는 평균 -111.66, 표준편차 16.63이며 관측 구간 내내 음수였다. 0으로 수렴하는 전략의 근거가 되지 않는다.
- 평균 근처 교차를 근거로 평균 대비 편차를 조사했다. 비용 초과 편차 900행은 독립적인 거래 900건도, 수익 실현 900건도 아니다.
- 분포 꼬리가 두꺼워 Z-score를 정규분포 발생확률로 해석하지 않는다.
- 같은 1시간으로 평균·표준편차를 구한 미래참조, 결측 및 전방 채움, 짧은 표본이 한계다.
- USDT/USDC 혼합 결과는 무효였다. 상품 ID, 기초자산 배수, 호가 및 정산 통화를 구분한다.

## 실행 가설과 초기 파라미터

동일 자산·동일 호가/정산 통화의 두 거래소에 대해 S = mid(A)-mid(B), Z = (S-과거 평균)/과거 표준편차다. Mid는 BBO에서 계산하며 별도 수집하지 않는다.

Z가 양수이면 A 매도/B 매수, 음수이면 A 매수/B 매도. 가격의 절대적 고저가 아니라 평상시 가격차 대비 상대적 고저를 거래한다. 양쪽 기초자산 수량을 같게 맞추며, 진입 평균·표준편차를 고정하여 움직이는 기준선만으로 청산 신호가 생기는 것을 막는다.

아래 숫자는 원문에서 입증된 값이 아닌 초기 검증 설정이다.

| 항목 | 설정 |
|---|---|
| 대상 | Bybit, Aster, GRVT, Hyperliquid / 기존 수집 유니버스 |
| 기준선 | 직전 900초, 최소 900개 유효한 1초 관측; 현재 관측은 평가 후 추가 |
| 진입 | 절대 Z >= 3, 예상 회귀 폭이 매수/매도 스프레드·왕복 수수료·슬리피지·추가 2bp를 초과 |
| 청산 | 진입 방향의 Z가 0.5 이하로 회귀, 시간 한도, 세션 종료, 손실 한도 |
| 데이터 | 수신 나이 <=1.5초, 거래소 시각 나이 <=2초, 양측 시각 차이 <=0.5초 |
| 결측 | 유효 기준선 관측 간격이 2초를 넘으면 warmup을 다시 시작. 연결 종료 시 해당 호가 제거 및 기준선 초기화 |
| 예상 슬리피지 | 체결당 1bp; 실측값이 아님 |

평균회귀는 보장되지 않는다. 추정 회귀 폭과 예상 청산 비용은 가정이며 실현 이익이 아니다. 현재 최소 주문 명목금액은 거래소별 보수적 바닥값일 뿐 상품별 필터 검증을 대체하지 않는다.

## 자금과 시간: 사용자 지정 + 명시적 해석

- 50달러 × 4거래소 = 200달러. 20%는 우선 **한쪽 주문의 명목금액 10달러**로 해석했다. 증거금 10달러에 레버리지를 곱해 주문을 늘리지 않는다.
- 거래소당 동시에 한 페어의 한쪽만, 동일 자산 중복 금지, 전체 최대 2페어. 총 진입 명목금액 최대 40달러. 수익이 나도 자동으로 규모를 늘리지 않고, 손실 시 축소한다.
- 초기 총자금의 10%인 20달러가 손실 중단 기준이다. 실현손익과 신선한 호가로 평가한 미실현 청산손익을 합한다. 실제 체결 실패·급변동에서는 정확한 20달러 손실 상한을 보장할 수 없다.
- Hyperliquid 최소 신규 주문은 10달러이므로 목표 10달러가 최소금액과 같다. 수량을 반올림해 한도를 넘기지 않으므로 정확히 맞추지 못하면 제외될 수 있다. 양쪽 최소수량/수량단위/잔량을 만족하지 못하면 확대하지 않고 제외한다.
- NYSE 정규 개장 09:30–10:30 America/New_York만 전략 실행. 한국시간 서머타임 22:30–23:30, 표준시 23:30–다음 날 00:30.
- 처음 15분은 세션 안에서 기준선을 만든다. 개장 전 실행 없이 시작하므로 개장 직후 바로 진입하지 않는다.
- 마지막 5분 신규 진입 금지, 종료 30초 전 청산 시도. 최대 보유 1시간보다 세션 종료가 우선한다.
- 주말·NYSE 휴장일 제외. 현재 캘린더는 검증된 2026년에 한정하고 이후 연도는 실행을 거절한다. 임시 휴장 공지는 별도 반영이 필요하다.

## 현재 구현 범위와 실거래 차이

`quant-trader`는 **shadow 전용**이다. 공개 WebSocket으로 BBO를 받아 가상 진입/청산을 기록한다. 비밀키를 읽지 않으며 사설 주문 API나 live 모드가 없다. config의 mode를 live로 바꾸면 거절한다.

- 실제 주문·서명·잔고조회·거래소 체결조회·부분 체결 복구는 아직 구현하지 않았다.
- 가상 체결은 양쪽 BBO가 동시에 전량 체결된다는 가정이다. 실제 지연·거절·부분 체결 성능으로 간주할 수 없다.
- 수수료는 기존 연구 설정이며 계정에서 조회한 확정 수수료가 아니다. 펀딩은 요청대로 수집하지 않으므로 출력 손익은 `excluding_funding`이다. 1시간 이하 보유도 펀딩을 피한다는 보장은 없다.
- 신규 신호 계산용 1초 타이머만 사용한다. 기존 수집·S3 서비스는 바꾸거나 중단하지 않는다. shadow는 별도 공개 연결을 사용한다.
- stale/잔량 부족으로 가상 청산도 평가할 수 없으면 `unresolved_shadow_exit`를 남기고 신규 진입을 중단한다. 실거래판에서는 이 상태를 해결할 때까지 관리 프로세스가 살아 있어야 한다.
- 동일 날짜의 로그를 덮어쓰지 않는다. 장애 뒤 운영자 검토 없이 위험 상태를 초기화해 재시작하지 않는다.

## 실행 및 배포

```
cargo test --locked --bin quant-trader
cargo build --release --locked --bin quant-trader
target/release/quant-trader --config config/trader-shadow.json --check
target/release/quant-trader --config config/trader-shadow.json
```

서버 출력 디렉터리는 `/var/lib/quant-trader-shadow`. timer는 뉴욕 09:30에 shadow service를 시작한다. `Persistent=false`여서 서버가 꺼져 있던 세션을 뒤늦게 따라 실행하지 않는다. Rust 코드도 실행 시각과 휴장일을 검증한다.

실거래 전에 필요한 작업: 별도 주문 어댑터 및 서명 테스트, 계정별 수수료/정밀도/최소금액/잔고 검증, 실제 체결 대조와 중복방지, 한쪽 체결 실패 복구, 재시작 복구, 펀딩/통화 처리 정책, 사용자 직접 활성화.

공식 근거: [NYSE 시간·휴장일](https://www.nyse.com/markets/hours-calendars), [Hyperliquid 주문 최소금액](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/error-responses).
